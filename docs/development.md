# Разработка ThinkCaps

## Локальная среда и Codex

Версия Flutter записана в [`.flutter-version`](../.flutter-version). Flutter 3.41.9 поставляется с Dart 3.11.5. Установите SDK из [архива Flutter](https://docs.flutter.dev/install/archive) и добавьте его каталог `bin` в `PATH` либо задайте `FLUTTER_ROOT` с путём к SDK. Скрипт также умеет найти Flutter в `android/local.properties` текущего или основного Git checkout.

Для проверок достаточно Flutter и PowerShell. Используйте `pwsh` в Linux и macOS, `pwsh` или встроенный `powershell` в Windows. Для сборки Android и запуска на устройстве нужны JDK 21 (как в CI), Android SDK и принятые лицензии SDK. Установите компоненты через Android Studio SDK Manager или `sdkmanager` и проверьте инструменты командой `flutter doctor -v`.

```sh
sdkmanager --install 'platforms;android-36' 'build-tools;36.1.0' 'ndk;28.2.13676358' 'cmake;3.22.1' 'platform-tools'
```

Команды из корня проекта. В Windows можно заменить `pwsh` на `powershell`.

| Команда | Что делает |
| --- | --- |
| `pwsh -NoProfile -File tool/check.ps1 setup` | Проверяет версию SDK и восстанавливает зависимости по `pubspec.lock`. |
| `pwsh -NoProfile -File tool/check.ps1` | Дополнительно проверяет форматирование, запускает анализатор и unit/widget-тесты. |
| `pwsh -NoProfile -File tool/check.ps1 android` | Выполняет все проверки и собирает debug APK. |
| `pwsh -NoProfile -File tool/check.ps1 device -DeviceId emulator-5554` | Запускает тест настоящего Dart ↔ Kotlin ↔ SQLite на выбранном Android. Подставьте ID из `flutter devices`. |

Codex читает [`AGENTS.md`](../AGENTS.md) в репозитории. Для независимых задач используйте режим Worktree и локальную среду ThinkCaps. [Конфигурация среды](../.codex/environments/environment.toml) запускает `setup` при создании worktree и добавляет действия «Проверить проект» и «Собрать debug APK». Для этих действий нужен `pwsh` в `PATH`. Во время проверки скрипт направляет локальные WebSocket-соединения Flutter в обход HTTP-прокси, сохраняя настройки прокси для внешних адресов.

GitHub Actions запускает режим `android` на pull request и при push в `main`. Сборка использует стандартный Android debug-ключ. Для PR укажите затронутый сценарий, результаты проверок и ограничения, особенно для данных и Android-поведения.

`ThinkCapsPlatform` вызывает `app.thinkcaps/bridge`. Kotlin передаёт в Dart событие `shareAvailable`, после которого Dart забирает очередь через `drainShares`. SQLite возвращает строки с `enDue/enStreak/enDays` и `ruDue/ruStreak/ruDays`. Сроки на границе моста — миллисекунды Unix. Dart вычисляет следующее состояние, а Kotlin обновляет столбцы указанного направления. Дубликаты определяются ограничением SQLite на английский термин, перевод и контекст. При ошибке ограничения мост возвращает `DUPLICATE`. При отмене выбора скриншота возвращается `null`.

## Ручные проверки

Экран повторения возвращает ошибочную попытку в очередь по сохранённому сроку. Если готовых карточек нет, экран ждёт ближайшего срока или позволяет вернуться на «Сегодня». Между направлениями одной пары действует минутная пауза после раскрытия ответа, которая отсчитывается заново после сохранения оценки. Пауза хранится в памяти приложения между сессиями повторения. Плановые сроки обоих направлений хранятся независимо в SQLite.

Используйте debug-сборку `app.thinkcaps.android.debug` на эмуляторе или выделенном устройстве. Она устанавливается рядом с релизной `app.thinkcaps.android` и использует отдельную SQLite. Пользовательские установки и предыдущие тестовые сборки с релизным ID сохраняют свои данные в своём пакете.

- **Карточки и SQLite.** Создайте запись с контекстом, отредактируйте перевод и перезапустите приложение. Проверьте сохранение изменений. При изменении схемы сначала создайте данные в debug APK с прежней схемой и тем же package ID, обновите его поверх и проверьте карточки и сроки обоих направлений.
- **Повторение.** Проверьте оба направления, раскрытие ответа касанием карточки и свайпы после раскрытия. На одной новой паре оцените первый ответ и проверьте, что обратное направление появляется через минуту. Отметьте ошибку и проверьте, что вопрос возвращается через пять минут на открытом экране. Повторите с несколькими парами и проверьте, что готовые карточки доступны во время паузы. Выйдите во время ожидания и проверьте, что «Сегодня» показывает ближайший срок. Коснитесь английского слова до и после переворота и проверьте произношение. Касание русского слова на лицевой стороне должно раскрыть ответ без звука. Повторное касание русского слова на раскрытой карточке также должно пройти без звука. Проверьте остановку озвучки при смене карточки и сворачивании приложения. Для изменений обработки TTS проверьте сценарий без установленного английского голоса.
- **Импорт.** Отправьте выделенный текст в ThinkCaps при холодном и тёплом запуске. Вставьте текст и импортируйте тестовый скриншот с прописными буквами. Откройте слово и проверьте контекст в карточке. Проверьте отмену выбора картинки.
- **Перевод.** Проверьте первый автоперевод с загрузкой модели, повторный перевод офлайн и ручной ввод при недоступной модели. Проверьте атрибуцию рядом с автоматическим переводом.
- **Быстрое добавление.** Откройте экран с «Сегодня» и из «Словаря». Добавьте подряд `curiosity`, `give up` и `break the ice`. Для первой карточки оставьте предложенный перевод, для второй выберите другой перевод и один пример, для третьей снимите выбор примера. После каждого сохранения проверьте пустое поле, фокус и возможность сразу вводить следующий термин. Проверьте карточки в словаре после выхода с экрана. Повторите сохранение той же комбинации, чтобы проверить сообщение о дубликате. Введите новое слово до завершения предыдущего поиска. При недоступном интернете проверьте повтор запроса и возможность сохранить свой перевод.

Device-тест использует свои синтетические карточки, проверяет дубликат, редактирование, независимость расписаний и удаление. Для сценариев с системным выбором файла, реальным OCR, загрузкой модели и TTS нужны ручные проверки на Android.

## Релизная сборка

Проверьте `version` в `pubspec.yaml`, увеличьте номер сборки для обновления APK и используйте существующий ключ релиза. Задайте `THINKCAPS_KEY_PROPERTIES` с абсолютным путём к файлу свойств вне репозитория. Свойства — `storeFile` (абсолютный путь к хранилищу), `storePassword`, `keyAlias`, `keyPassword`.

Выполните `flutter build apk --release`. Проверьте подпись `apksigner verify --print-certs build/app/outputs/flutter-apk/app-release.apk` и сравните отпечаток сертификата с предыдущим релизом. Перед публикацией проверьте установку поверх предыдущей версии и сохранение карточек на тестовом устройстве.
